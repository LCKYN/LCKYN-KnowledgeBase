# Sampling Algorithms

## Overview

**Sampling algorithms** draw a subset or random values from a population or distribution with known probabilities. Data engineers use them to subsample streams and tables (**reservoir**, **stratified**); ML engineers use them to estimate expectations (**Monte Carlo**, **importance sampling**); LLM engineers use them to pick the next token (**temperature**, **top-k**, **top-p**).

## Key Concepts

| Concept | Description |
|---------|-------------|
| **With vs without replacement** | Can the same item be picked twice? |
| **Uniform vs weighted** | Equal probability vs probability proportional to weight $w_i$ |
| **Streaming** | Population size $n$ unknown up front; one pass, $O(k)$ memory |
| **Stratification** | Sample each subgroup separately to keep group proportions |
| **Proposal distribution** | Easy distribution $q$ used to sample a hard target $p$ |
| **Monte Carlo error** | Estimation error shrinks as $O(1/\sqrt{n})$, independent of dimension |

## Comparison Table

| Algorithm | Input | Replacement | Memory | Use when |
|-----------|-------|-------------|--------|----------|
| `random.sample` | In-memory sequence | No | $O(k)$ | Data fits in memory |
| `random.choices(weights=)` | In-memory + weights | Yes | $O(n)$ | Bootstrap, weighted resampling |
| **Reservoir (Algorithm R)** | Stream, unknown $n$ | No | $O(k)$ | Logs, Kafka topics, huge files |
| **Weighted reservoir (A-Res)** | Stream + weights | No | $O(k)$ | Weighted sample from a stream |
| **Stratified** | Labelled table | No | $O(n)$ | Imbalanced classes, eval splits |
| **Rejection** | Target density $p$ | — | $O(1)$ | Easy bounding proposal exists |
| **Importance** | Target $p$, proposal $q$ | — | $O(1)$ | Estimate $\mathbb{E}_p[f]$, rare events |

## Reservoir Sampling

Keep the first $k$ items; item $i$ (0-based) then replaces a random slot with probability $k/(i+1)$. Every item ends up in the sample with probability exactly $k/n$.

```python
import random

def reservoir(stream, k):
    res = []
    for i, x in enumerate(stream):
        if i < k:
            res.append(x)
        elif (j := random.randrange(i + 1)) < k:
            res[j] = x
    return res
```

**Weighted, without replacement** (Efraimidis–Spirakis A-Res): give each item the key $u^{1/w}$ with $u \sim U(0,1)$ and keep the $k$ largest keys.

```python
import heapq, random

def weighted_reservoir(stream, k):  # stream of (item, weight > 0)
    return heapq.nlargest(k, stream, key=lambda p: random.random() ** (1 / p[1]))
```

> [!TIP] Distributed Version
> A-Res merges cleanly: each worker keeps its top-$k$ keys, then the driver takes the top-$k$ of the union. Same trick works for uniform reservoir (key = $u$).

## Stratified Sampling

Sample a fixed fraction **within each group** so rare classes are not lost by chance.

```python
df.groupby("label", group_keys=False).sample(frac=0.1, random_state=0)   # pandas
train_test_split(X, y, test_size=0.2, stratify=y, random_state=0)       # sklearn
```

## Rejection and Importance Sampling

**Rejection sampling**: draw from an easy proposal, keep the draw only if it falls under the target. Acceptance rate = area under target / area under proposal envelope.

```python
def sample_unit_disk():
    while True:                          # accept rate pi/4 ~ 79%
        x, y = random.uniform(-1, 1), random.uniform(-1, 1)
        if x * x + y * y <= 1:
            return x, y
```

**Importance sampling**: sample from $q$, reweight by the likelihood ratio.

$$
\mathbb{E}_{p}[f(x)] = \mathbb{E}_{q}\left[f(x) \frac{p(x)}{q(x)}\right] \approx \frac{1}{n} \sum_{i=1}^{n} f(x_i) \frac{p(x_i)}{q(x_i)}, \quad x_i \sim q
$$

> [!WARNING] High-Dimensional Rejection
> Acceptance rate falls exponentially with dimension (unit ball in a cube: 79% in 2D, ~0.25% in 10D). Use MCMC or importance sampling instead.

## Token Sampling (LLM Decoding)

The model outputs logits $z_i$; decoding turns them into a choice. **Temperature** $T$ rescales before softmax ([[13.14 Softmax]]):

$$
p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}
$$

| Method | Rule | Effect |
|--------|------|--------|
| **Greedy** ($T \to 0$) | Always argmax | Deterministic, repetitive |
| **Temperature** | Divide logits by $T$ | $T < 1$ sharper, $T > 1$ flatter |
| **Top-k** | Keep $k$ most likely tokens, renormalise | Cuts long tail; fixed $k$ ignores confidence |
| **Top-p (nucleus)** | Keep smallest set with cumulative prob $\geq p$ | Adaptive: few tokens when confident, many when not |
| **Min-p** | Keep tokens with $p_i \geq p_{min} \cdot p_{max}$ | Scales cut-off with top token's confidence |

```python
import math, random

def top_p_sample(probs, p=0.9, temperature=1.0):   # probs: {token: prob}
    w = {t: math.exp(math.log(q) / temperature) for t, q in probs.items()}
    total, kept, mass = sum(w.values()), [], 0.0
    for t in sorted(w, key=w.get, reverse=True):
        kept.append(t)
        mass += w[t] / total
        if mass >= p:
            break
    return random.choices(kept, weights=[w[t] for t in kept])[0]
```

- Order in most engines: temperature → top-k → top-p/min-p → sample.
- Real engines work on logits with log-softmax for numerical stability; the snippet uses probabilities for clarity.

## Practical Use Cases

| Scenario | Technique |
|----------|-----------|
| 1M-row sample from a 10B-row log stream | Reservoir sampling |
| Eval set that keeps rare-class ratio | Stratified sampling |
| Bootstrap confidence intervals | `random.choices` with replacement |
| Downsample majority class for training | Stratified / weighted sampling ([[12.14 Imbalanced Classification]]) |
| Off-policy evaluation, rare-event estimation | Importance sampling |
| Creative text vs extraction / JSON output | Top-p with $T \approx 0.7$–$1.0$ vs greedy / $T = 0$ |
| Self-consistency (sample many CoT paths, vote) | Temperature sampling ([[11.13 Chain of Thought]]) |
