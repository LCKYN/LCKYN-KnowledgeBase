# Gradient Boosting

## Overview
**Gradient boosting** builds an additive model of shallow decision trees, where each new tree is fit to the **negative gradient of the loss** with respect to the current prediction. It is gradient descent in function space: instead of updating weights, each step adds a tree that moves predictions downhill. It is the default strong model for tabular data.

## Key Concepts
- **Additive model** — the prediction is a sum of trees, built one at a time: $F_m(x) = F_{m-1}(x) + \nu \, h_m(x)$.
- **Pseudo-residuals** — the target each tree $h_m$ is trained on: the negative gradient of the loss at the current prediction, $r_{im} = -\partial L(y_i, F_{m-1}(x_i)) / \partial F_{m-1}(x_i)$.
- For squared error the pseudo-residual is just the residual $y_i - F_{m-1}(x_i)$; other losses (log loss, quantile, ranking) only change this formula.
- **Shrinkage** ($\nu$, the learning rate) — scales each tree's contribution. Smaller $\nu$ generalizes better but needs more trees.
- **Stochastic gradient boosting** — each tree sees a random subset of rows and/or columns, which decorrelates trees and reduces variance.
- **Early stopping** — stop adding trees when validation loss stops improving; this sets the tree count instead of tuning it.

### Algorithm
1. Initialize $F_0$ as the constant that minimizes the loss (mean for squared error, log-odds for log loss).
2. For each round $m$: compute pseudo-residuals → fit a shallow tree $h_m$ to them → update $F_m = F_{m-1} + \nu h_m$.
3. Predict with the final sum $F_M$.

### Key Hyperparameters
Names follow XGBoost / LightGBM; other libraries use different names for the same knobs.

| Hyperparameter | Effect | Guidance |
| :--- | :--- | :--- |
| `learning_rate` | Step size per tree | 0.01-0.1; lower is better if you can afford the trees |
| `n_estimators` | Number of trees | Set high and let early stopping pick |
| `max_depth` / `num_leaves` | Tree complexity, interaction order | Depth 3-8; the main overfitting lever |
| `subsample`, `colsample_bytree` | Row / column sampling per tree | 0.6-0.9 adds regularization |
| `min_child_weight`, `reg_lambda` | Leaf-level regularization | Raise when overfitting on small data |

> [!TIP]
> `learning_rate` and `n_estimators` trade off against each other — fix a small learning rate, use early stopping for the tree count, then tune depth and sampling. Search strategies are in [[12.09 Hyperparameter Tuning]].

## Comparison Table

| Aspect | XGBoost | LightGBM | CatBoost |
| :--- | :--- | :--- | :--- |
| **Tree growth** | Level-wise (default) | Leaf-wise | Symmetric (oblivious) trees |
| **Signature idea** | Second-order gradients + explicit regularization | Histogram splits with GOSS and feature bundling | Ordered boosting to avoid target leakage |
| **Categorical features** | Supported, less mature | Native | Best-in-class (ordered target statistics) |
| **Speed on large data** | Fast | Fastest | Slower to train, fast to predict |
| **Out-of-the-box quality** | Good, benefits from tuning | Good, leaf-wise overfits small data | Strongest defaults |

## Practical Use Cases
- **Use it for** structured/tabular problems: churn, fraud, credit risk, demand forecasting with engineered features, learning-to-rank.
- **Strengths** — no feature scaling needed, handles missing values natively, captures non-linearities and interactions, supports custom losses.
- **Skip it for** raw images, audio, and text (deep learning), tiny or near-linear datasets (linear models), or when a noisy-label baseline is enough (Random Forest).

> [!WARNING]
> - **No extrapolation** — trees predict a constant per leaf, so predictions go flat outside the training feature range. Trending time series need detrending or differencing first.
> - **Overfits without early stopping** — unlike Random Forest, more trees eventually hurts.
> - **Sensitive to label noise and outliers** — use a robust loss (Huber, quantile) if targets are dirty.
> - **Class imbalance** — tune `scale_pos_weight` or the decision threshold; see [[12.14 Imbalanced Classification]].
