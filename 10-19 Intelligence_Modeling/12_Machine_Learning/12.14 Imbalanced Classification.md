# Imbalanced Classification

## Overview
**Imbalanced classification** is any classification task where one class is much rarer than the others: fraud, churn, defects, rare diseases, abuse. The model can score high accuracy by always predicting the majority class, so the real work is picking the right **metric**, the right **decision threshold**, and only then deciding whether to reweight or resample.

## Key Concepts

- **Imbalance ratio**: majority count / minority count. 10:1 is mild, 1000:1 is extreme
- **Accuracy paradox**: at 1% positives, "always negative" scores 99% accuracy and catches nothing
- **The problem is often too few positives, not the ratio**: 500 positives in 50k rows is learnable; 20 positives is not, no matter the technique
- **Probabilities vs decisions**: a model outputs scores; the threshold turns them into actions. Most imbalance pain is a threshold problem, not a training problem
- **Cost asymmetry**: a missed fraud and a false alarm rarely cost the same. Put real costs on FN and FP and optimize those

## Metrics

| Metric | What it measures | Use when |
|---|---|---|
| **Precision** | Of flagged, how many are real: $\frac{TP}{TP+FP}$ | False alarms are expensive (manual review queue) |
| **Recall** | Of real positives, how many caught: $\frac{TP}{TP+FN}$ | Misses are expensive (fraud, disease) |
| **F1 / F-beta** | Harmonic mean; $\beta > 1$ weights recall | One number at a fixed threshold |
| **PR-AUC** (average precision) | Precision-recall trade-off over all thresholds | **Default ranking metric** under heavy imbalance |
| **ROC-AUC** | TPR vs FPR over thresholds | Comparing rankers; looks optimistic when negatives dominate |
| **MCC** | Correlation of predictions and labels, uses all 4 cells | Balanced single-number summary |
| **Recall @ fixed precision** (or vice versa) | Business-shaped operating point | "We can review 200 alerts a day" |
| **Log loss / Brier** | Probability quality | When scores feed downstream decisions or pricing |

> [!INFO] Why ROC-AUC flatters
> FPR $= \frac{FP}{FP+TN}$ has the huge TN count in the denominator, so thousands of false positives barely move it. Precision has no TN term and shows them. The PR-AUC of a random model equals the positive rate, not 0.5.

## Techniques

### 1. Fix the evaluation first
- **Stratified splits** and stratified k-fold ([[12.08 Cross-Validation]]) so every fold has positives
- Time-based splits for fraud and churn: imbalance often shifts over time
- Report metrics on the **true** class distribution, never on a resampled test set

### 2. Threshold tuning (cheapest, often enough)
- Train normally, then pick the threshold on a validation set that maximizes F-beta, expected profit, or recall at a required precision
- With costs $C_{FP}$, $C_{FN}$ and calibrated probabilities, the cost-optimal threshold is:

$$t^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$$

- 0.5 is only right when costs are equal and probabilities are calibrated

### 3. Class weights / cost-sensitive loss
- Scale each sample's loss by its class weight so minority errors cost more
- `class_weight="balanced"` in scikit-learn ([[12.04 Logistic Regression]], SVM, trees) sets weights inversely proportional to class frequency
- XGBoost `scale_pos_weight` (docs suggest $\frac{\#\text{neg}}{\#\text{pos}}$ as a start), LightGBM `is_unbalance` / `scale_pos_weight`, CatBoost `auto_class_weights` ([[12.11 Gradient Boosting]])
- Deep learning: weighted [[13.13 Cross Entropy]] or **focal loss** $FL = -(1-p_t)^\gamma \log p_t$, which down-weights easy, confidently correct examples

### 4. Resampling (training set only)
| Method | How | Watch out |
|---|---|---|
| **Random undersampling** | Drop majority rows | Loses data; fine when majority is huge, speeds up training |
| **Random oversampling** | Duplicate minority rows | Overfits duplicates |
| **SMOTE** and variants | Interpolate synthetic minority points between neighbours | Weak on high-dim, categorical, or noisy data; often no better than weights for boosted trees |
| **Ensembles of balanced subsets** | Train many models on different undersampled sets (balanced bagging, EasyEnsemble) | More models to manage |

- Library: `imbalanced-learn` (pipelines that resample only inside each CV fold)

### 5. Reframe the problem
- **Anomaly detection** (Isolation Forest, autoencoders) when positives are too few or too varied to learn
- **Get more positives**: active learning, labelling near the threshold, weak supervision
- **Two-stage**: cheap high-recall filter, then a precise model or human review

## Calibration After Reweighting

> [!WARNING] Resampling and weights distort probabilities
> Training on a 50/50 sample makes the model believe positives are common, so its scores are inflated. Rankings (AUC) are fine; probabilities are not. Fix with:
> - **Recalibration** on an untouched validation set (Platt scaling, isotonic regression)
> - **Prior correction** after undersampling negatives at rate $\beta$: $p = \frac{\beta p_s}{\beta p_s - p_s + 1}$ (Dal Pozzolo et al., 2015)

## Practical Recipe

1. Pick the business metric and operating point (cost matrix or review capacity)
2. Strong baseline: gradient boosting on the raw distribution, evaluated by PR-AUC
3. Tune the threshold on validation
4. Try class weights; keep them only if the metric improves at your operating point
5. Try resampling last, inside CV folds only
6. Calibrate if probabilities are consumed downstream; monitor positive rate drift in production ([[24.01 Model Drift Detection]])

> [!WARNING] Common mistakes
> - Resampling **before** the train/test split: synthetic points leak into the test set
> - Reporting accuracy or ROC-AUC alone
> - Tuning the threshold on the test set
> - Assuming SMOTE is required; for tree ensembles, weights or threshold tuning usually match it with less risk

## Practical Use Cases
- **Fraud and abuse**: extreme imbalance, time splits, recall at a fixed review budget
- **Churn and conversion**: moderate imbalance, calibrated probabilities for targeting
- **Medical screening**: high-recall threshold, then a precise second test
- **Manufacturing defects**: few positives, often anomaly detection plus active labelling
- **LLM classifiers** (toxicity, intent): same metrics apply; few-shot examples must also be label-balanced ([[11.14 Prompt Engineering]])
