# Jev

## Overview
**Jev** is a hosted **decision model** API from **TypeSafe AI** (launched Sep 2026). It doesn't generate text. It answers **typed questions** about an input and returns a structured judgment with probabilities. TypeSafe calls this category **System One**, after Kahneman's fast, intuitive thinking. Generative LLMs are the slow, deliberate **System Two**.

> [!INFO] Core idea
> "Jev makes the judgment, while application code makes the move." The model only classifies. Policy, thresholds, and actions stay in your code.

## Key Concepts

- **Typed judgments**: every question has a type declared up front, so the answer space is bounded by the developer
  - **Choice**: pick one option from a closed list (e.g., `billing` / `technical` / `other`), with a probability for every option
  - **Score**: place the input on an ordered scale or rubric (e.g., relevance 0–5, risk low/med/high)
  - **Noul**: probability that a yes/no statement is true
- **Probabilities + confidence**: outputs are calibrated numbers you can threshold on, not prose to parse
- **State in, decision out**: send the request state plus several questions and get all answers in one call
- **`/v1/systemone` protocol**: the API contract, which open models like [[11.57 Laya]] also implement
- **Closed weights**: API only, with no self-hosting or fine-tuning

```python
decision = jev.classify(state=request, questions={
    "risk": Score(rubric=["low", "medium", "high"]),
    "needs_tool": Noul("Does this need a tool call?"),
})
if decision.risk == "high": return request_human_review(request)
```

## Jev vs Generative LLM

| Aspect | Jev (System One) | Generative LLM (System Two) |
|---|---|---|
| **Output** | Choice / Score / Noul + probabilities | Free text or open-ended JSON |
| **Answer space** | Developer-defined, enumerable | Open-ended |
| **Latency** | ~150–300 ms per API call | Seconds (token-by-token decode) |
| **Hallucination surface** | None in output (bounded labels) | Any generated text |
| **Best for** | Classify, route, rank, block, escalate | Generate, summarize, explain, reason |

## Reported Specs (Sep 2026)

| Metric | Value |
|---|---|
| Pricing | ~$0.042 / 1M input tokens, output free |
| Latency (p50, single question) | ~150–276 ms, including network (236–276 ms for v1.13.0 in Laya's benchmark) |

> These figures come from launch-week blogs and vendor claims, and sources disagree on some of them. Benchmark on your own data before you rely on them.

## Practical Use Cases

Choose Jev when:
- **The output is executable**: it drives routing, permissions, tool selection, or escalation
- **The answer space is bounded**: every valid answer can be listed in advance
- **Uncertainty should gate automation**: send low-confidence or high-risk cases to a human
- **Latency matters**: decisions need to fit a ~70–500 ms budget
- **You want zero ops**: no GPUs to run, many options per question, or you just want to try the category

Stick with an LLM for copywriting, code generation, summarization, open-ended reasoning, and conversation.

> [!EXAMPLE] Hybrid pipeline
> 1. Jev classifies the task type, difficulty, and sensitivity.
> 2. Simple work goes to a cheap or fast model, hard work to a strong one.
> 3. The LLM generates the answer.
> 4. Jev checks the output (safe? on-policy?).
> 5. Application code takes the final action.

> [!TIP] Evaluation
> Measure end-to-end metrics (cost, latency, escalation rate, downstream errors), not only per-question accuracy. Thresholds are your responsibility.
