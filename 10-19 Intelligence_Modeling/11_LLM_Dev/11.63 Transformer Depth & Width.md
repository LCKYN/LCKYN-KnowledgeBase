# Transformer Depth & Width

## Overview
A transformer LLM's **shape** is set by a handful of size hyperparameters: **depth** (number of blocks), **width** ($d_{model}$), attention heads, and MLP size. Sizes within a model family share one architecture template and differ only in these numbers.

## Key Concepts
- **Layer = block**: one **layer** = one **transformer block** = one attention sublayer + one MLP sublayer
- **$d_{model}$**: width of the residual stream that every block reads from and adds to
- **$d_{ff}$**: hidden size of the MLP inside each block
- **Attention heads / KV heads**: with **GQA**, several query heads share one key-value head
- Exact values are in `config.json` (`num_hidden_layers`, `hidden_size`, `intermediate_size`, `num_attention_heads`, `num_key_value_heads`)

## Same Family, Different Sizes
Sizes share one **architecture template** (same block type, norm, activation, positional encoding, tokenizer); only size hyperparameters change.

| Llama 3.1 | 8B | 70B | 405B |
|---|---|---|---|
| Layers | 32 | 80 | 126 |
| $d_{model}$ | 4,096 | 8,192 | 16,384 |
| Attention heads | 32 | 64 | 128 |
| KV heads (GQA) | 8 | 8 | 8 |
| MLP hidden ($d_{ff}$) | 14,336 | 28,672 | 53,248 |

- Both **depth and width grow** together; Kaplan et al. (2020) found shape matters much less than total params within a wide range
- **Exceptions**: Llama 2 7B/13B use MHA but 70B uses GQA; small Qwen2.5 models tie embeddings; some families mix dense and MoE sizes (e.g., Qwen3)
- Sizes are **separate weight sets**, not shrunken copies of each other
  - Some small models are derived from bigger ones: Llama 3.2 1B/3B are pruned from 8B then distilled; Gemma 2 2B/9B are distilled from a larger teacher

## Can Layer Sizes Differ?
- **$d_{model}$ (residual width)**: effectively fixed — every layer *adds* into the same stream, so dimensions must match. Changing it needs projections and breaks the clean residual path; rare in mainstream LLMs
- **Inside a block**: free to vary — $d_{ff}$, number of heads, head size
  - **OpenELM** (Apple, 2024): *layer-wise scaling* — fewer heads / smaller MLP early, larger later
  - **MoE**: e.g., DeepSeek-V3 keeps the first few layers dense, MoE after
  - **Hybrids**: interleave full attention with sliding-window or state-space (Mamba) layers

## Changing Shape After Training
- **Pruning**: drop whole layers or shrink width — details in [[11.40 Pruning & Sparsity]]
  - Gromov et al. (2024) remove many deeper layers with small benchmark loss after a brief healing fine-tune
  - ShortGPT removes low-influence layers with no healing at all
  - NVIDIA **Minitron** prunes depth and width, then distills
- **Growth**: reuse a trained small model to start a larger one
  - **Net2Net**: function-preserving widening and deepening
  - **LiGO**: learns a linear map from small weights to the larger model's initialization

> [!WARNING] Pruned ≠ intact
> Factual recall survives layer removal fairly well; multi-step reasoning and long-context ability usually degrade more. "Redundant" layers may be redundant only for some tasks.

## Closed Models (Claude, GPT, Gemini)
- Anthropic publishes **no** parameter counts, layer counts, or dense-vs-MoE details; Haiku / Sonnet / Opus are price–speed–capability tiers
- Public numbers are third-party guesses from pricing and throughput — unreliable because of MoE (active vs total params), pricing strategy, hardware, and quantization
- Even Anthropic's own interpretability papers cite only relative positions ("middle layer"), not layer counts

## Practical Use Cases
- Read `config.json` before picking layers for probing, activation patching, or adapter targets
- Compare layers across sizes by **relative depth**, not by index
- Don't base cost or capability comparisons on parameter estimates for closed models
