# Laya

## Overview
**Laya** is an open-source (**Apache 2.0**), **non-autoregressive System One decision model** from **Convai Innovations**. It takes a text/JSON **state** plus **typed questions** and returns answers with **calibrated probabilities** in ~33 ms, across 100+ languages. There's no text generation, so nothing to hallucinate or parse. It's the self-hostable counterpart of [[11.56 Jev]] and serves the same `/v1/systemone` API shape.

## Key Concepts

- **Architecture**: encoder backbone plus a small **decision head**
  - Backbone: **ModernBERT-large** (395M) → 421M total, or **mmBERT-base** for the multilingual checkpoint (322M)
  - Head: 2 transformer layers, an **option-marker scorer** (each option is scored at its own `[MASK]` token), and an **act/escalate head**
- **Four question primitives**
  - `choice`: categorical selection; options are softmaxed
  - `score`: ordinal scale (the weakest primitive)
  - `noul`: probability that a yes/no statement is true
  - `action`: routing with `act_probability` (currently unreliable)
- **Router**: detects script/language in under 0.5 ms and picks the best checkpoint. `Router(preload=True)` keeps routing under 35 ms.
- **Training (RLCD, Reinforcement Learning for Calibrated Decisions)**: the policy outputs distributions and exploration adds zero-mean Gaussian noise. The reward is a **strictly proper scoring rule** (log, spherical, RPS). Updates use REINFORCE with a group-mean baseline, the same idea as [[11.52 GRPO]]. The goal is that probabilities *mean* something.
- **Token budget is tight**: the English checkpoint has a 512-token context (~320 for the state, `head_max_len=192` for questions and options)

```python
from laya import Router
result = Router().predict(state, questions)
result["answers"]["department"]["choice"]   # + per-option probabilities
result["routing"]["model"]                  # which checkpoint answered
```

## Checkpoints

| Checkpoint | Encoder | Params | Context | Best for |
|---|---|---|---|---|
| `convaiinnovations/laya` | ModernBERT-large | 421M | 512 | English, guardrails, email triage |
| `convaiinnovations/laya-multilingual` | mmBERT-base | 322M | 1,024 (up to 8,192) | 100+ languages, long docs, 2.2× faster |
| `convaiinnovations/laya-typed-decisions` | ModernBERT-large | 421M | 1,024 | Typed-decision workflows (fine-tuned) |

## Deployment

- `pip install laya` (Python 3.10+), with extras: `[serve]` HTTP, `[mcp]` MCP server, `[langchain]`, `[onnx]`, `[fast]` GPU
- `laya-serve` exposes `POST /v1/systemone` on `:8000`, compatible with Jev's API shape. Auth comes from the `LAYA_API_KEY` env var.
- Runs on GPU, CPU, or in the browser via ONNX. Air-gapped deployments work, and data never leaves your infra.

## Laya vs Jev (model card, Tesla T4)

| Aspect | Laya | Jev 1.13.0 |
|---|---|---|
| **License** | Apache 2.0, open weights | Closed, API only |
| **Latency (1 question)** | **32.8–39.5 ms** | 236–276 ms p50 (incl. network) |
| **Batched** | 10 questions in 72–159 ms (103–332 q/s) | n/a |
| **Typed-decisions acc.** | **0.766** (`laya-typed-decisions`) | 0.727 |
| **Calibration (ECE)** | **0.081** after temp. scaling (0.466 raw) | 0.144 after temperature |
| **Many options (50+)** | Weak: only ~3–4 tokens per label | Strong |
| **Long input** | 512 tokens (English); 8k with multilingual | Tens of k tokens |
| **Fine-tuning** | Yes, and essentially required | No |
| **Cost** | Free weights; pay for compute | ~$0.042 / 1M input tokens |

> [!WARNING] Known limitations (from the model card)
> - **Base checkpoints are near chance zero-shot**: 0.362 on typed-decisions vs 0.766 fine-tuned. You need to fine-tune on your domain.
> - **Ships over-confident**: fit a temperature per (question type, option count) before you trust probabilities (ECE 0.466 → 0.081).
> - **High-cardinality `choice`** (50+ options) squeezes labels. Raise `head_max_len` or split into hierarchical questions.
> - **`score` is weakest** (SST-5 acc. 0.372).
> - **`noul` may follow label names instead of the state.** A neutral-key `choice` works better.
> - **`action.act_probability` is unusable.** Gate on `confidence` instead (AUROC 0.77).

> [!WARNING] Multilingual confidence trap
> One community test reported the English checkpoint at **0.080 accuracy on Bengali with 0.945 confidence**. Always go through the **Router**, not a single English checkpoint, when inputs may be non-Latin script.

## Practical Use Cases

Choose Laya over Jev when:
- **Latency is critical**: in-process decisions ~7× faster than an API round trip
- **Privacy or air-gap is required**: regulated data, on-prem, edge, or browser
- **Volume is high**: no per-call fee
- **You can fine-tune**: a domain-tuned checkpoint beats Jev on accuracy and calibration
- **Label sets are small and inputs short**: routing, intent classification, guardrail yes/no checks, email triage

Choose Jev instead for zero ops, no labeled data to fine-tune on, 50+ options, or long inputs.
