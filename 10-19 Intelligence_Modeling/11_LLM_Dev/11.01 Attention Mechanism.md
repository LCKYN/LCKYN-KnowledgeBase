# Attention Mechanism

## Definition
**Attention** is a mechanism that allows neural networks to focus on specific parts of the input sequence when processing data, rather than treating the entire input as a fixed-size vector. It mimics cognitive attention.

## Key Concepts
- **Query, Key, Value (Q, K, V)**: The core components of attention.
    - **Query**: What I am looking for.
    - **Key**: What I can offer.
    - **Value**: What I actually contain.
- **Self-Attention**: Relates different positions of a single sequence to compute a representation of the sequence.
- **Cross-Attention**: Queries come from one sequence (decoder), keys and values from another (encoder output, image patches). Used in encoder-decoder and multimodal models.
- **Multi-Head Attention**: Runs multiple attention mechanisms in parallel to capture different types of relationships.

## Importance
- **Solves Long-Range Dependencies**: Unlike RNNs/LSTMs, attention connects distant words directly.
- **Parallelization**: Enables parallel processing of sequences (unlike sequential RNNs), leading to the **Transformer** architecture.

## Scaled Dot-Product Attention

Each token's hidden state $x$ is projected into $q = xW_Q$, $k = xW_K$, $v = xW_V$. For a sequence of $n$ tokens stacked as matrices $Q, K \in \mathbb{R}^{n \times d_k}$, $V \in \mathbb{R}^{n \times d_v}$:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + M\right) V$$

- $QK^\top$: an $n \times n$ matrix of similarity scores, one per (query, key) pair
- **Scale by $\sqrt{d_k}$**: dot products grow with dimension; without scaling, [[13.14 Softmax]] saturates to near one-hot and gradients vanish
- **Softmax** per row turns scores into weights that sum to 1
- Output: each token gets a weighted average of all value vectors
- $M$: the mask (0 where allowed, $-\infty$ where blocked)

## Causal Mask

Decoder-only LLMs predict the next token, so token $i$ must not see tokens $j > i$:

$$M_{ij} = \begin{cases} 0 & j \le i \\ -\infty & j > i \end{cases}$$

- Makes training parallel: all $n$ next-token predictions are computed in one pass
- Makes generation incremental: past tokens never change, so their keys and values can be cached
- **Padding masks** block pad tokens in batched inputs; encoders (BERT) use no causal mask, so every token sees both sides

## Multi-Head Attention

$$\text{MHA}(X) = \text{Concat}(\text{head}_1, \dots, \text{head}_h)\, W_O, \quad \text{head}_i = \text{Attention}(XW_Q^i, XW_K^i, XW_V^i)$$

- Split $d_{\text{model}}$ into $h$ heads of size $d_{\text{head}} = d_{\text{model}} / h$; total compute is about the same as one big head
- Each head learns a different pattern (local syntax, coreference, copying, induction heads; see [[11.62 Mechanistic Interpretability]])
- Head count and size are depth/width choices ([[11.63 Transformer Depth & Width]])

## KV Cache

During generation each new token needs attention over **all previous** keys and values. Recomputing them every step is wasteful, so they are stored: the **KV cache**.

- **Prefill**: process the prompt in parallel, fill the cache (compute-bound)
- **Decode**: one token at a time, read the whole cache each step (memory-bound; see [[11.18 LLM Throughput & Memory Bound]])
- Cache size per token: $2 \times n_{\text{layers}} \times n_{\text{kv\_heads}} \times d_{\text{head}} \times \text{bytes}$, so it grows linearly with context length and batch size
- Reusing a cached prefix across requests is [[11.21 Prompt Caching]]; paging it (vLLM PagedAttention) cuts fragmentation ([[11.27 LLM Generation Engines]])

## MQA, GQA, MLA: Shrinking the KV Cache

| Variant | Idea | KV heads | Trade-off |
|---|---|---|---|
| **MHA** (Vaswani et al., 2017) | Every query head has its own K, V | $h$ | Best quality, largest cache |
| **MQA** (Shazeer, 2019) | All query heads share **one** K, V head | 1 | Smallest cache; some quality loss, less stable training |
| **GQA** (Ainslie et al., 2023) | Query heads split into $g$ groups, one K, V per group | $g$ (e.g. 8) | Near-MHA quality at a fraction of the cache; the default in Llama 2 70B / Llama 3 and most open models |
| **MLA** (DeepSeek-V2, 2024) | Compress K, V into a low-rank **latent** vector; cache only the latent, up-project at use | Latent of size $d_c \ll h \cdot d_{\text{head}}$ | Large cache reduction with MHA-level quality; more complex, needs special RoPE handling |

- These change the **architecture**, so they are chosen at pre-training (or by uptraining a checkpoint), unlike post-hoc KV quantization ([[11.39 Quantization]])
- Fewer KV heads means more sequences fit in memory, so higher decode throughput

## Complexity

| | Time | Memory |
|---|---|---|
| Attention scores (training / prefill) | $O(n^2 d)$ | $O(n^2)$ for the score matrix if materialized |
| One decode step with KV cache | $O(n d)$ | $O(n d)$ cache per layer |
| Projections + MLP (for contrast) | $O(n d^2)$ | $O(n d)$ |

- Quadratic in $n$ is what limits context length ([[11.16 Context Window Management]]); at short context the MLP dominates, at long context attention does
- **[[11.38 Flash Attention]]** keeps the same math but tiles the computation in SRAM so the $n \times n$ matrix is never written to HBM: memory becomes $O(n)$, time is still $O(n^2 d)$ but much faster in practice
- Sub-quadratic alternatives: **sliding-window attention** (each token sees the last $w$), sparse patterns, linear attention and state-space models, often mixed with full-attention layers

> [!WARNING] Common confusions
> - Flash Attention is an **exact** kernel optimization, not an approximation and not a new architecture
> - GQA/MQA shrink the **KV cache**, not the attention FLOPs of prefill much
> - Long context windows are not free: the cache, not the weights, often dominates GPU memory at long context ([[11.75 Long Context vs RAG]])
