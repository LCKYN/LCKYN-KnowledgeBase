# Sparse Autoencoder (SAE)

## Overview
A **sparse autoencoder** adds a sparsity constraint to the latent layer: for any input, only a few latent units are active. The latent is usually **overcomplete** (wider than the input), so sparsity, not size, is what prevents copying. Originally a method for unsupervised feature learning, it is now the main tool for decomposing LLM activations into interpretable features.

## Key Concepts
- **Loss**: $L = \lVert x - \hat{x} \rVert^2 + \lambda \lVert z \rVert_1$ — reconstruction plus a sparsity penalty
- **Dictionary learning view**: each decoder column is a **feature direction**; an input is rebuilt as a sparse sum of a few directions
- **Standard form for LLM activations**: $z = \text{ReLU}(W_{enc}(x - b_{dec}) + b_{enc})$, $\hat{x} = W_{dec} z + b_{dec}$
- **Expansion factor**: latent width ÷ input width; commonly 8× to 64× or more
- **$L_0$**: average number of active latents per input — the real sparsity measure
- **Sparsity vs reconstruction**: a Pareto trade-off; variants are compared by their frontier, not a single point

## Variants

| Variant | Sparsity mechanism | Note |
|---|---|---|
| **KL-sparsity** (classical) | KL between mean activation and a target rate | Sigmoid units; Ng's 2011 lecture notes |
| **L1 (ReLU)** | L1 penalty on activations | Simple; suffers **shrinkage** (activations pushed too low) |
| **k-sparse / TopK** | Keep the top $k$ activations, zero the rest | Sets $L_0$ directly, no shrinkage (Makhzani & Frey, 2013; Gao et al., 2024) |
| **BatchTopK** | Top-k across the whole batch | Lets the per-input count vary (Bussmann et al., 2024) |
| **Gated** | Separate "which fire" from "how strongly" | Removes shrinkage (Rajamanoharan et al., 2024) |
| **JumpReLU** | Learned threshold per feature, $L_0$ penalty | Used in Gemma Scope (Rajamanoharan et al., 2024) |
| **Matryoshka** | Nested dictionaries of increasing size | Reduces feature splitting and absorption (Bussmann et al., 2025) |

Related architectures that reuse the sparse dictionary idea:
- **Transcoder**: reconstructs an MLP's *output* from its *input* → a sparse, interpretable replacement for the MLP (Dunefsky et al., 2024)
- **Crosscoder**: one dictionary reads and writes across several layers or models → shared features and model diffing (Anthropic, 2024)

## Evaluation

| Metric | What it measures |
|---|---|
| **$L_0$** | Sparsity: active latents per input |
| **MSE / variance explained** | Reconstruction quality |
| **Loss recovered** | Model's loss when its activation is replaced by the reconstruction |
| **Dead latents** | Fraction that never fire |
| **Dense latents** | Fraction that fire on most inputs (usually uninterpretable) |
| **Auto-interpretability** | How well an LLM-written label predicts where a feature fires |

> [!WARNING] Common pitfalls
> - **Dead latents**: units that stop firing never recover; fix with resampling or an auxiliary loss on dead units
> - **Shrinkage**: L1 trades activation magnitude for sparsity; prefer TopK, Gated, or JumpReLU
> - **Feature splitting**: a larger dictionary splits one feature into several narrower ones
> - **Feature absorption**: a general feature fails to fire where a specific one takes over
> - **Reconstruction error**: the unexplained residual may hold the part you care about

## Practical Use Cases
- **LLM interpretability**: find monosemantic features in the residual stream; see [[11.62 Mechanistic Interpretability]]
- **Steering**: clamp or amplify a feature to change model behavior
- **Classical feature learning**: sparse codes from images resemble edge detectors, like early visual cortex

> [!TIP] Starting point
> Use pre-trained dictionaries (Gemma Scope on Neuronpedia) before training your own. If training, start with **TopK**: one hyperparameter ($k$) and no shrinkage.
